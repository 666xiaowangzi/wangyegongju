👑 产品概览与技术元信息

一个自包含的单文件 SketchUp 扩展，把「插件仓库 + 启动器 + 功能聚合 HUD + 快捷检索」四件事合并到同一套 UI 里。

本插件是一个 SketchUp Ruby 扩展，全部逻辑写在单一文件 xwzglq.rb 内，包含 Ruby 后端（文件系统操作、插件加载、配置持久化、安全守卫）与内联前端（HtmlDialog 承载的完整 HTML/CSS/JS 单页应用）。它解决的核心痛点是：SketchUp 原生 Plugins 目录一旦插件过多，就会出现启动缓慢、工具栏爆炸、找不到功能、无法分类、难以迁移五大问题。

本插件的做法是把插件从原生目录「收纳」到自己的库目录，改为按需启动；同时通过猴子补丁劫持 UI::Command 的构造过程，把每一个插件注册的每一个功能（命令）记录进「功能池」，从而实现跨插件的功能级检索与再编排——你可以把 A 插件的第 3 个命令和 B 插件的第 7 个命令拖进同一条自定义工具条里。

📦 安装、首次启动与卸载

两种安装方式，一次重启，零配置即可用。首次运行会自动建立库目录与默认配置。

方式 A：扩展程序管理器安装（推荐）

  1. 准备 .rbz 包
    把 xwzglq.rb 与 xwztb.png 放进一个文件夹，压缩为 zip，再把扩展名改为 .rbz。注意：两个文件必须位于压缩包根目录，不要多套一层文件夹。
  2. 打开管理器
    SketchUp 菜单：窗口 → 扩展程序管理器（Extension Manager）。
  3. 安装
    点击左下角 安装扩展程序（Install Extension），选择刚才的 .rbz 文件，确认安全提示。
  4. 重启
    完全退出并重新启动 SketchUp。这一步不可跳过——工具栏与菜单在扩展注册期创建。

方式 B：手工拷贝

  1. 定位 Plugins 目录
    在 Ruby 控制台执行 Sketchup.find_support_file("Plugins") 获取真实路径；或使用本插件菜单里的「打开原生 Plugins 目录」（若已装过旧版）。
  2. 拷贝文件
    将 xwzglq.rb 与 xwztb.png 直接放入该目录。
  3. 重启 SketchUp
    重启后即完成安装。
Windows 常见路径：
C:\Users\<用户名>\AppData\Roaming\SketchUp\SketchUp 20XX\SketchUp\Plugins\

macOS 常见路径：
~/Library/Application Support/SketchUp 20XX/SketchUp/Plugins/

首次启动时后台自动执行的动作

  1. EnvironmentGuard.setup_safe_environment：为 6 个高频缺失库创建 DummyModule 代理占位。
  2. UI::Command 猴子补丁生效：此后任何插件创建的命令都会被 HUDTracker 记录。
  3. load_auto_start_plugins：先加载「基础库」目录，再加载所有 0000 前缀的自启动插件，最后按配置生成自定义原生工具条。
  4. HUDTracker.flush_hud_persistent：把内存中采集到的功能记忆确定性地一次性落盘到 xwzhud.json（不依赖定时器，绝不漏写）。
  5. 注册 on_quit 钩子：SketchUp 退出前再落盘一次，防止启动期延迟写入因提前退出而丢失。
  6. create_toolbar：创建工具栏、菜单、快捷键搜索命令并 set_accelerator。
  7. UI.start_timer(0) 预热：后台预构建大面板 HTML 与 HUD 功能池，让首次点击无需等待。
注册期全程被兜底
用 begin/rescue 把整个注册流程包住。即使发生任何异常，也只会在 Ruby 控制台打印 ❌ [Loader] 扩展注册失败（已隔离，SketchUp 仍可正常启动），绝不会冒泡到 SketchUp 核心导致启动崩溃。这意味着「装了这个插件导致 SU 打不开」在设计上不可能发生。

🗂️ 目录结构与数据文件

所有状态落在两个 JSON 文件里，全部采用「临时文件 + 备份 + 原子重命名」写入，断电不损坏。

两个关键路径

名称取值逻辑说明
install_pathxwzglq.rb 所在目录即 SketchUp 原生 Plugins 目录
library_path默认 install_path/xwzxwz；若存在 xwzdiy.json 则读取其中记录的自定义路径插件库根目录，所有被管理的插件、配置、回收站都在这里

完整目录树

<install_path>/                        ← SketchUp 原生 Plugins 目录
├─ xwzglq.rb                          主程序
├─ xwztb.png                          工具栏图标
├─ xwzdiy.json                        [可选] 自定义库路径记录（DIY_PATH_FILE）
└─ xwzxwz/                            默认库目录（DEFAULT_FOLDER_NAME）= library_path
   ├─ config.json                     主配置（CONFIG_FILE，schema_version = 3）
   ├─ config.json.tmp                 原子写入中间文件（写完立即 rename，正常不可见）
   ├─ config.json.bak                 上一次成功写入的备份
   ├─ config.json.bak.<时间戳>         配置结构迁移时自动保留的历史存档（按时间戳命名）
   ├─ xwzhud.json                     HUD 功能池离线记忆
   ├─ xwzhud.json.bak                 功能池备份（主文件损坏时自动回滚）
   ├─ 基础库/                          BASE_LIB_NAME，最高优先级加载
   │  ├─ Fredo6_LibFredo6/            （典型：公共依赖库放这里）
   │  └─ SUAPI-CommonLib/
   ├─ _recycle_bin/                   RECYCLE_BIN 回收站（非永久删除）
   │  └─ 某个被删插件/
   ├─ 0000常用建模插件/                0000 前缀 = 已开启自启动
   ├─ 0000材质工具/
   ├─ 曲面工具箱/                      无前缀 = 需手动启动
   └─ 渲染农场/
目录命名的三条铁律
① 0000 前缀是功能性标记，代表自启动，不要手工添加或删除，请用面板的「⚡ 自启」开关；② _recycle_bin 与 基础库 是保留名，不要用作普通插件文件夹名；③ 插件文件夹名会被 sanitize_name 清洗，其中的 / \ : * ? " < > | 会被替换为下划线。

config.json —— 主配置

承载全部用户数据：分组、备注、真名映射、排序、联动工具、书签、自定义工具条、面板位置、主题、视图模式等。写入策略为延迟落盘：调用 update_config(defer: true) 时先改内存，再起一个 500ms 定时器合并写盘，避免拖拽排序这类高频操作把磁盘打爆。面板关闭、SketchUp 退出、执行重要操作前都会调用 flush_config_deferred 强制落盘。

xwzhud.json —— 功能池离线记忆

这是本插件最具特色的数据文件。它记录了每个插件曾经注册过的每一个命令：所属插件文件夹、命令标题、图标路径。有了它，即使插件当前尚未加载，HUD 面板依旧能把它的全部功能列出来；当你点击其中一个功能时，后端 HUDTracker.execute 会先按需加载该插件（睡眠唤醒），再执行对应命令块。

文件作用损坏时的行为
xwzhud.json功能池主数据JSON 解析失败时自动尝试读取 .bak 恢复
xwzhud.json.bak上一次成功写入的完整备份主备皆损坏 → 视为空池，长按 🔄 可重建

原子写入机制 atomic_write

1. 内容先写入  <目标文件>.tmp
2. 若目标文件已存在 → 复制一份为 <目标文件>.bak
3. File.rename(tmp, 目标文件)   ← 文件系统级原子操作
4. 任一步失败 → 保留 .bak，原文件不受影响
为什么要这么麻烦
SketchUp 崩溃或断电常发生在写盘瞬间。直接 File.write 会留下半截 JSON，导致下次启动配置全丢。原子重命名保证「要么是旧的完整文件，要么是新的完整文件」，不存在中间态。

同一套数据、三种密度：大面板管理，小面板日常，搜索面板极速。

面板默认尺寸打开方式定位方式定位目标

面板模式的记忆与切换

  • panel_mode 只记录 large / small 两个值；搜索面板是临时呼出，不写入此键。
  • toggle_panel_mode：在大/小之间来回切，关闭当前面板并打开另一个。
  • show_main_panel：读取 panel_mode 决定开哪个——这就是「上次用小面板，下次点工具栏仍是小面板」的原因。
  • 面板位置分别记忆：panel_pos 是一个嵌套 Hash，形如 { large:{...}, small:{left,top,width,height}, shortcut:{...} }。

光标定位与 DPI 换算（Windows）

搜索面板需要「在鼠标附近弹出」，这在 HtmlDialog 里没有现成 API。源码通过 Fiddle 直接调用 Windows user32.dll：GetCursorPos 取物理像素光标坐标，GetSystemMetrics 取屏幕尺寸，再计算 DPI 缩放系数，把物理坐标换算成 HtmlDialog 使用的逻辑坐标。同时做边界夹紧：面板不会因为光标靠近屏幕边缘而跑出可视区。

macOS 行为差异
Fiddle 调用 user32.dll 属于 Windows 专有。在 macOS 上这部分被安全跳过，搜索面板将退回到系统默认位置（通常屏幕中央）弹出，其余功能完全一致。

🕹️ 聚合 HUD 面板与功能池（核心特色）

跨插件的功能级检索与再编排——把任意插件的任意命令，拼装成属于你自己的工具条。

原理：劫持 UI::Command 构造函数

源码中对 UI::Command 做了猴子补丁，用 alias_method 保留原实现，然后重写 initialize、small_icon=、large_icon=、tooltip=、menu_text= 五个方法。

# 简化示意
class UI::Command
  alias_method :__xwz_orig_initialize, :initialize
  def initialize(title, &block)
    __xwz_orig_initialize(title, &block)
    folder = MyPlugin::Loader.current_loading_folder || "External"
    HUDTracker.register_cmd(folder, title, self, block)   # ← 记录：谁、叫什么、怎么执行
  end

  alias_method :__xwz_orig_small_icon=, :small_icon=
  def small_icon=(path)
    self.__xwz_orig_small_icon = path
    HUDTracker.update_cmd_icon(self, path)                # ← 补记图标
  end
  # tooltip= / menu_text= 同理：补记更友好的中文标题
end
  • 归属判定：命令归属于「当前正在加载的插件文件夹」（current_loading_folder）。若命令是在插件加载完成之后才动态创建的，归属记为 External。
  • 标题优先级：update_cmd_title(source: :tooltip) 会用 tooltip / menu_text 覆盖构造时的原始标题——因为很多插件构造时传英文，之后才设中文 tooltip。
  • 执行块被保存：register_cmd 连同 block 一起存入内存，这是「HUD 里点一下就能跑」的前提。

离线记忆与「睡眠唤醒」

内存中的 block 在 SketchUp 重启后就没了，但 xwzhud.json 里的文本记录还在。于是产生了本插件最巧妙的一个行为：

  1. 冷启动
    SketchUp 刚启动，绝大多数插件没有被加载，内存中没有它们的命令。
  2. HUD 依然满格
    打开聚合 HUD 面板，cached_functions 从 xwzhud.json 读出历史记录，所有插件的所有功能照常列出。
  3. 点击某个功能
    前端调用 execute_hud_cmd(plugin, title)。
  4. 后端按需唤醒
    HUDTracker.execute 检查该插件是否已加载：未加载 → 立即 load_plugin(plugin)，加载完成后从新注册进来的命令里找到同名 title，调用其 block。
  5. 结果
    用户感知上是「点一下功能就执行了」，实际上后台完成了一次完整的插件加载。这就是「按需启动」与「功能可检索」两个目标的统一。
睡眠唤醒的两个前提
① 插件必须仍在库目录中（被删或改名会导致唤醒失败）；② 唤醒依赖标题精确匹配——若插件升级后改了命令标题，旧记录会失效。此时长按 🔄 强制刷新即可按新的 @commands 合并重建。

功能池 UI 与自定义工具条

区域内容操作
右侧「提取池」按插件分组列出全部历史命令，带图标点击选中 / Ctrl 多选 / 框选；右键加入工具条；Ctrl+A 全选提取池
左侧「自定义工具条」你编排出来的工具条列表拖拽命令进出；拖拽调整顺序；双击标题重命名；右键删除工具条
工具条上的 ● 圆点原生映射开关（autostart）点亮后调用 create_native_toolbar，在 SketchUp 界面上瞬间生成一条真正的原生工具条
过滤无图标命令
build_ui_pool(filter_no_icon: true) 是预热时的默认调用。很多插件会注册一些没有图标的内部命令（分隔符、隐藏项），默认将其过滤掉以保持功能池整洁。

分块下发机制

功能池数据量可能非常大（数千条）。CEF 的 execute_script 对单条脚本长度有隐性上限，超长会被静默丢弃。源码用 HUD_CHUNK_SIZE = 200 把数据切成每 200 条一块，通过 window.appendHudChunk(arr, isLast) 流式追加，彻底规避了「插件多了 HUD 就白屏」的问题。

为什么所有数据都要 Base64
SketchUp 的 CEF 在 execute_script 传递含中文的 JSON 时存在 UTF-8 编码腐蚀问题（中文变乱码）。源码的对策是：所有下发数据先 JSON 序列化 → Base64 编码 → 前端 decodeBase64Json 解码。这是整个前后端通信的统一约定，也是本插件中文名显示始终正确的根本原因。

④ 插件体检 🩺

这是本插件最激进的功能。diagnose_plugins 会逐个加载选中的插件，并观察其副作用：

  1. 调用 do_diagnose_load(folder) 加载单个插件。
  2. 加载后检查：该插件是否创建了工具条（UI::Toolbar.new 被 NameCatcher 钩住）或注册了扩展（register_extension 被钩住）。
  3. 两者皆无 → 判定为无效插件，自动移入回收站。
  4. 两者有其一 → 判定为正常，保留。
  5. 特殊豁免：检测到插件是 RubyEncoder 加密的，直接判为成功跳过（加密插件的注册行为不可观测）。
  6. 全过程分步执行，进度实时回传；ESC 可中断。
体检前务必先打包备份
体检会真实地把判定失败的插件移入回收站。虽然回收站不是永久删除、可以一键还原，但某些「只提供 Ruby API、不创建任何 UI」的库类插件（例如纯函数库、公共依赖）会被误判为失败。建议：把这类库先「移入基础库」再体检，或体检后立刻检查回收站。

📚 分组、联动工具、书签与基础库

四种组织维度，互不冲突：分组是归属，联动是编排，书签是外链，基础库是优先级。

插件分组

  • 一个插件只能属于一个分组（plugin_map 是 插件名 → 分组名 的一对一映射）。
  • 默认分组是保留分组：不能重命名、不能删除。删除其它分组时，其成员自动回落到默认分组（不会丢失）。
  • 移动方式：拖拽卡片到侧栏分组 / 右键菜单 / batch_move_plugins 批量移动。
  • 侧栏分组条目本身可拖拽排序，顺序持久化。

联动工具（Bundle）

  • 把 N 个插件打成一个「启动组」，点 ▶️ 一次性全部启动（前端把成员用逗号拼接后调 load_plugins）。
  • 典型用法：「建模日」= 曲面工具 + 参数化 + 快速倒角；「出图日」= 渲染器 + 材质库 + 后期。
  • 一个插件可以同时属于多个联动工具（与分组的一对一不同）。
  • update_bundle_content 可更新成员；双击标题 rename_bundle 重命名。

基础库（BASE_LIB_NAME = 基础库）

library_path/基础库/ 是一个特权目录，其中的插件在 load_auto_start_plugins 中最先加载，早于所有 0000 自启动插件。

  • 用途：存放公共依赖库。典型如 Fredo6_LibFredo6——数十个 Fredo6 系列插件都依赖它，必须先于它们加载。
  • 源码对 Fredo6 有特殊处理：load_plugin_dir 中针对基础库内的 Fredo6 目录有专门的加载路径处理逻辑。
  • 移入：右键「📚 移入基础库」或把卡片拖到侧栏「📚 基础库」上（move_to_base_lib）。
  • 移出：在基础库视图内右键「📤 移出基础库」（move_out_of_base_lib）。
  • 强烈建议：把纯函数库、无 UI 的依赖库放进基础库——这样它们不会被「插件体检」误判为无效而丢进回收站。

收纳原生插件 🧲

  1. 扫描
    点 🧲 或在空白处右键「扫描收纳原生插件」，触发 fetch_native_plugins，列出原生 Plugins 目录中所有不受本管理器管理的插件。
  2. 勾选
    在弹出列表中勾选要接管的插件，并指定目标分组（默认为当前视图所在分组，否则为「默认分组」）。
  3. 迁移
    migrate_selected_plugins 把它们从原生目录移动到 library_path，从此改为按需启动。
收纳会真实移动文件
被收纳的插件不再自动加载。如果你依赖它每次开机就在，请在收纳后为它开启「⚡ 自启」，或把它放进「📚 基础库」。

配置版本迁移（智能继承）

🛡️ 四重安全守卫机制

本插件对其它插件做了大量劫持，因此内建了四道防线以保证「劫持不出事、出事不扩散」。

🌍
EnvironmentGuard
缺失依赖库代理。为 YUN / SS / TT / Fredo6 / JHS / MSPhysics 六个高频缺失库创建 DummyModule 占位，让引用它们的插件不会因 NameError 直接崩溃。
🧪
SandboxGuard
用 TracePoint 监控 String / Array / Hash / Float / Integer / Sketchup::Model / UI::Command 七个核心类是否被恶意修改，一旦发现即报警。
🚫
PopupGuard
批量操作期间拦截插件弹窗，防止「加载 50 个插件弹 50 个对话框」把流程卡死。
🏷️
NameCatcher
钩住 register_extension、UI::Toolbar.new、UI::Toolbar#show，捕获插件的真实名称，解决「文件夹名和显示名对不上」。

EnvironmentGuard —— 缺失库代理

KNOWN_MISSING_LIBS = ['YUN', 'SS', 'TT', 'Fredo6', 'JHS', 'MSPhysics'].freeze

def self.setup_safe_environment
  KNOWN_MISSING_LIBS.each do |lib|
    next if Object.const_defined?(lib)
    Object.const_set(lib, DummyModule.new(lib))   # 建立代理占位
  end
end

为什么需要：大量国产插件依赖 SS、YUN 等公共库。若用户只装了子插件没装库，加载时会抛 NameError: uninitialized constant SS 并中断整个批量加载流程。DummyModule 让这些引用静默降级，插件可能部分功能不可用，但不会拖垮整体加载。

PopupGuard —— 弹窗拦截

被拦截的调用说明
UI.messagebox最常见的插件启动提示 / 广告 / 版权声明
UI.inputbox要求用户输入的阻塞对话框
UI.openpanel文件打开选择器
UI.savepanel文件保存选择器
HtmlDialog#show_modal模态 HTML 对话框
Win32API 级弹窗绕过 SketchUp API 直接调 Windows MessageBox 的插件
拦截仅在批量操作期间启用（批量启动、插件体检），操作结束后立即恢复。正常单个启动插件时弹窗行为不受影响。

NameCatcher —— 真名捕获

SketchUp 插件的文件夹名、扩展注册名、工具栏名三者常常完全不同（例如文件夹叫 su_solidtools，注册名叫 Solid Tools Pro，工具栏叫 实体工具）。NameCatcher 在加载期钩住这三个入口，把捕获到的名字记入 true_names，让界面上能显示对用户有意义的名称，也是「🔍 提取真名」功能的数据来源。

整体异常隔离策略

  • 注册期：整个 register_extension + create_toolbar 被 begin/rescue 包裹，失败仅打印，SU 照常启动。
  • 自启动期：load_auto_start_plugins 被 rescue 包裹，单个插件失败不影响其余。
  • 预热期：get_html_content 预构建失败仅打印「预热失败（不影响功能）」。
  • 可选依赖：win32ole 加载失败被 rescue LoadError 吞掉。
  • 文件操作：拷贝、重命名等关键调用普遍带 rescue nil 兜底。
  • 落盘：注册 UI.add_event_handler(:on_quit)，退出前强制 flush，防止延迟写入丢失。

  • 按文件名关键词加分（如含 icon / logo / main / 插件名本身）。
  • 按目录深度减分（越靠近根目录越可能是主图标）。

C. 平台与环境限制

  • Windows 专有：Fiddle 调用 user32.dll 实现的光标定位与 DPI 换算；PowerShell Expand-Archive 解压；Win32API 弹窗拦截。
  • macOS 退化行为：搜索面板改为系统默认位置弹出；解压退回 unzip 命令；Win32 弹窗拦截不适用（macOS 无此路径）。
  • 需要 HtmlDialog：即 SketchUp 2017 及以上版本（HtmlDialog 类在 2017 引入）。
  • 中文路径：Windows 下图标路径做了 encode('filesystem') → GBK 的双重兜底；但仍建议库目录路径不含特殊符号。
  • 单实例假设：面板对象存为模块变量（@dialog_instance / @small_dialog），同一时刻同类型面板只有一个。
